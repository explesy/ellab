# AGENTS.md — инструкции для ИИ-агентов

Этот файл читают агенты (pi и др.) перед работой с репозиторием «Эллаб». Здесь правила проекта; общие правила агента действуют поверх них.

## Что это за проект

«Эллаб» — русскоязычный интерактивный учебник по электротехнике на Astro + Starlight. Цель: от физических основ (заряд, ток, напряжение, сопротивление) к электрике зданий и солнечной/автономной энергетике, с ориентацией на Германию и Испанию.

Сайт публикуется через GitHub Pages с базой `/ellab`. Учебный проект **не выдаёт квалификацию** и не допускает работ с сетью 230/400 В.

## Команды

```bash
npm ci                              # установка (предпочтительно npm ci, как в CI)
npm run dev                         # локальный сервер
npm test                            # тесты формул (node --test)
npm run build                       # сборка в dist/
node scripts/check-generated-pages.mjs   # проверка собранного сайта (после build)
```

Перед коммитом обязательно выполнить `npm test`, `npm run build` и `node scripts/check-generated-pages.mjs`. Все три должны пройти.

## Нумерация уроков

Номер урока для читателя — это метка в меню, заголовке и тексте. Имена файлов сохраняют прежние адреса (GitHub Pages и внешние ссылки), поэтому имена **не переименовывать** без редиректа.

| Метка | Файл | Тема |
|---|---|---|
| 01 | `00-introduction` | Введение |
| 02 | `01-quantities` | Ток, напряжение, сопротивление |
| 03 | `02-ohms-law` | Мощность и энергия |
| 04 | `03-series-parallel` | Соединение нагрузок |
| 05 | `04-alternating-current` | Переменный ток |

Аудиоверсии имеют метку «N А» (например, «02А»). Файлы `*-audio.md` не входят в меню и открываются ссылкой из урока.

## Структура урока (обязательна)

Источник: `notes/teaching-guidelines.md`. Каждый урок должен содержать:

1. Вступительный вопрос или наблюдение из реальной жизни.
2. Аудиотекст на 15–25 минут (файл `*-audio.md`), ссылка из визуального конспекта и обратно.
3. Визуальный конспект: определения, обозначения, единицы, формулы (`FormulaCard`).
4. Интерактивная часть: лаборатория или график с предсказанием.
5. Вопросы на понимание (2–6) с ответами в `<details>` или в конце; хотя бы одна **расчётная задача с полным решением**.
6. Раздел «Критерий освоения»: что ученик может объяснить, вычислить, предсказать и где границы модели.
7. Словарь DE/ES (таблица; термины урока; без выдуманных терминов).
8. Переход к следующему уроку.

## Правила содержания

- **Физика и числа.** Все числа в тексте должны совпадать с тестами в `tests/`. Если добавляешь числовой пример — добавь тест.
- **Модели.** Всегда указывать границы: идеальный источник, омическое R, постоянная температура, синусоида. Не приписывать постоянное R лампам, диодам, PV.
- **Ватт и ватт-час** различать явно. **Мощность провода** и **мощность нагрузки** различать явно.
- **Действующее и амплитудное** значения: 230 В — RMS, амплитуда ≈ 325 В.
- **Условное направление тока** и дрейф электронов — отмечать.
- **Русский язык.** Единицы: В, А, Ом, Вт, Вт·ч, Гц. Десятичная запятая в тексте, точка в коде.
- **Не перезаписывать архивы.** `notes/archive/` и архивные аудио (`00-introduction` — версия 1.0) не правим. Новая редакция — новый файл или новый коммит с записью в changelog.
- **Не добавлять** личный учебный журнал в публичный репозиторий.

## Безопасность (жёстко)

- Никаких инструкций по работе с сетью 230/400 В, щитами, PV-стрингами, автоматами и УЗО как «сделай сам».
- Опыты только в симуляторе или на изолированных низковольтных учебных стендах с ограничением тока.
- Короткое замыкание не предлагать проверять опытом.
- Мультиметр в режиме тока не подключать поперёк источника.
- Выбор сечения и автомата — только как «нужен расчёт специалиста по нормам».

## Интерфейс и компоненты

- Лаборатории — Astro-компоненты с `<script>`. Формулы импортировать из `src/lib/electricity.mjs`, не дублировать.
- Ползунки имеют видимую подпись и `aria-live` для результата.
- Формулы в `FormulaCard` писать на LaTeX (например, `I_{\text{ср}} = \dfrac{\Delta Q}{\Delta t}`). KaTeX рендерит их в HTML + MathML при сборке; новая формула должна проходить `tests/formula-rendering.test.mjs`.
- Формулы внутри абзацев и решений в MDX рендерить через `InlineMath` из `src/components/InlineMath.astro` (например, `<InlineMath expression="I=\frac{dQ}{dt}" />`). Не записывать математику обычной строкой или моноширинным кодом; новые выражения проверяются в `tests/inline-formulas.test.mjs`.
- Новые лаборатории: `src/components/*.astro`, подключать в MDX через `import`.
- Не менять `dist/`, `node_modules/`, `.astro/` вручную.

## Перед сдачей изменений (чек-лист агента)

1. `npm test`, `npm run build`, `node scripts/check-generated-pages.mjs` — зелёные.
2. Если меняется список уроков или их адреса — обновить `astro.config.mjs`, `scripts/check-generated-pages.mjs` и карту в этом файле.
3. Все внутренние ссылки между уроками и аудио проверены (относительные пути `../`).
4. В `notes/lesson-changelog.md` добавлена запись о содержательных изменениях.
5. В ответе пользователю: какие файлы изменены и что не проверено (например, визуальная проверка в браузере).

## Что агент не должен делать без явного запроса

- Публиковать (`git push`, включать Pages), менять настройки репозитория.
- Удалять архивы, редиректы или старые аудиоверсии.
- Выдавать в тексте уроков профессиональные рекомендации по монтажу как готовое руководство.
